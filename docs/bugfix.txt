## 🐛 BUG #1 — Onboarding existing user'a da gösteriliyor

**Symptom:** Var olan (returning) kullanıcı login olduğunda onboarding flow tekrar tetikleniyor. Sadece **yeni kullanıcılara** (first-time signup) gösterilmeli.

**Hipotez (root cause):**
- `onboarding_completed` flag'i `users` tablosunda persist edilmiyor veya
- AsyncStorage'dan okunuyor ama Apple Sign-In sonrası user record fetch edilmeden navigation kararı veriliyor (race condition)
- Auth state restore sırasında `isNewUser` flag yanlış set ediliyor

**Aksiyon:**
1. `users` tablosunda `onboarding_completed_at TIMESTAMPTZ` kolonu var mı kontrol et. Yoksa migration ekle:
```sql
   ALTER TABLE users ADD COLUMN IF NOT EXISTS onboarding_completed_at TIMESTAMPTZ;
   CREATE INDEX IF NOT EXISTS idx_users_onboarding ON users(onboarding_completed_at) WHERE onboarding_completed_at IS NULL;
```
2. Auth flow'da (muhtemelen `app/_layout.tsx` veya `contexts/AuthContext.tsx`):
   - Login sonrası **önce** `users` tablosundan profil çek
   - `onboarding_completed_at IS NULL` → onboarding route'una yönlendir
   - Değilse → ana feed'e
3. Onboarding son adımında (archetype quiz finish):
```ts
   await supabase
     .from('users')
     .update({ onboarding_completed_at: new Date().toISOString() })
     .eq('id', userId);
```
4. AsyncStorage'a **fallback cache** yaz ama **source of truth DB olsun**.

**Test:**
- Yeni user signup → onboarding görür ✅
- Logout → tekrar login → onboarding GÖRMEMELİ ✅
- App'i sil, tekrar yükle, aynı Apple ID ile login → onboarding GÖRMEMELİ ✅

## 🐛 BUG #2 — Premium üye Settings → "Manage Subscription" basınca paywall'a giremiyor

**Symptom:** Aktif premium aboneliği olan kullanıcı Settings ekranında "Manage Subscription"a tıkladığında **"You are already a premium member"** uyarısı çıkıyor ve **paywall (subscription management screen) açılmıyor**. Bu yanlış — premium kullanıcı plan değiştirmek/iptal etmek isteyebilir.

**Hipotez (root cause):**
- "Manage Subscription" butonu paywall component'ine yönlendirilmiş ama paywall component'in başında `if (isPremium) return <AlreadyPremium />` guard'ı var
- Bu guard sadece **upgrade flow'da** olmalı, **manage flow'da** olmamalı
- iOS native subscription management URL'ine (`itms-apps://apps.apple.com/account/subscriptions`) yönlendirilmesi gerekiyor

**Aksiyon:**
1. Settings ekranındaki "Manage Subscription" handler'ı bul (muhtemelen `app/(tabs)/settings.tsx`).
2. Premium kullanıcılar için **doğrudan iOS native subscription management'a** yönlendir:
```ts
   import { Linking, Platform } from 'react-native';
   
   const handleManageSubscription = async () => {
     if (isPremium) {
       const url = Platform.OS === 'ios' 
         ? 'itms-apps://apps.apple.com/account/subscriptions'
         : 'https://play.google.com/store/account/subscriptions';
       await Linking.openURL(url);
     } else {
       router.push('/paywall'); // upgrade flow
     }
   };
```
3. Paywall component'indeki `isPremium` guard'ı kaldırma — orada kalsın ama **entry point'i ayır**:
   - `/paywall` → upgrade için (free → premium)
   - `Linking.openURL(...)` → manage için (premium kullanıcı)
4. RevenueCat'in `Purchases.showManageSubscriptions()` API'sini de değerlendir — daha native bir UX sağlar:
```ts
   import Purchases from 'react-native-purchases';
   await Purchases.showManageSubscriptions();
```
   **Tercih:** RevenueCat API'si, fallback olarak Linking.

**Test:**
- Free user → "Manage Subscription" → paywall açılır ✅
- Premium user → "Manage Subscription" → iOS subscription settings açılır ✅
- Premium user → upgrade akışına yanlışlıkla düşmez ✅

## 🐛 BUG #3 — Mood arama kotası azalmıyor (CRITICAL — revenue leak)

**Symptom:** Kullanıcı "Find a Mood" özelliğini onboarding'de 1 kez kullandı, sonra **kendi isteğiyle 3 kez daha** kullandı. Ekranda hâlâ "2 left today" yazıyor. **Kota düşmüyor, unlimited kullanım mümkün.**

**Hipotez (root cause):** En kritik bug. Birkaç olası neden:
1. **Quota decrement RPC fail-silent çalışıyor:** `decrement_mood_quota` Edge Function veya RPC çağrısı hata veriyor ama UI hatayı yutuyor
2. **Cache invalidation eksik:** DB'de quota düşüyor ama UI eski state'i gösteriyor (stale cache)
3. **Onboarding quota'sı production quota'sından ayrı sayıyor:** Onboarding "free trial" sayılıp ana quota'ya işlenmiyor
4. **V1.0.2'deki "kota bypass fix"** regresyon yarattı — fix sırasında decrement çağrısı kaldırılmış olabilir

**Aksiyon (önem sırası):**

### 3.1 — Quota decrement'i atomic ve server-side yap
Quota client-side decrement edilmemeli. Mood parse Edge Function'ı **çağrılmadan ÖNCE** server-side atomic decrement yapılmalı.

```sql
-- migrations/014_atomic_quota_decrement.sql
CREATE OR REPLACE FUNCTION decrement_mood_quota(p_user_id UUID)
RETURNS TABLE (
  success BOOLEAN,
  remaining INT,
  reason TEXT
) AS $$
DECLARE
  v_user RECORD;
  v_today DATE := CURRENT_DATE;
BEGIN
  -- Lock the user row to prevent race conditions
  SELECT subscription_tier, daily_quota_used, daily_quota_reset_at, weekly_quota_used, weekly_quota_reset_at
  INTO v_user
  FROM users
  WHERE id = p_user_id
  FOR UPDATE;

  -- Reset daily quota if new day
  IF v_user.daily_quota_reset_at IS NULL OR v_user.daily_quota_reset_at < v_today THEN
    UPDATE users SET daily_quota_used = 0, daily_quota_reset_at = v_today WHERE id = p_user_id;
    v_user.daily_quota_used := 0;
  END IF;

  -- Check tier-based limit
  DECLARE
    v_limit INT;
  BEGIN
    v_limit := CASE v_user.subscription_tier
      WHEN 'free_trial' THEN 1
      WHEN 'weekly' THEN 2
      WHEN 'monthly' THEN 3
      WHEN 'yearly' THEN 3
      ELSE 0
    END;

    IF v_user.daily_quota_used >= v_limit THEN
      RETURN QUERY SELECT FALSE, 0, 'daily_limit_reached';
      RETURN;
    END IF;

    -- Atomic decrement
    UPDATE users 
    SET daily_quota_used = daily_quota_used + 1
    WHERE id = p_user_id;

    RETURN QUERY SELECT TRUE, (v_limit - v_user.daily_quota_used - 1), 'ok';
  END;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;
```

### 3.2 — Edge Function'da decrement'i ZORUNLU yap
`supabase/functions/parse-mood/index.ts`:
```ts

}

// Sadece quota başarılı düştükten SONRA Claude API'yi çağır

```

## 🐛 BUG #4 — Settings → "Clear Watchlist" çalışmıyor

**Symptom:** Settings ekranındaki "Clear Watchlist" butonuna basıldığında watchlist temizlenmiyor.

**Hipotez (root cause):**
1. RLS policy `DELETE` izni vermiyor
2. Confirmation dialog'dan sonra delete handler tetiklenmiyor
3. `eq('user_id', userId)` filter'ı eksik veya yanlış
4. Local state (Zustand/Redux/Context) invalidate edilmiyor — DB silindi ama UI gösteriyor

**Aksiyon:**

### 4.1 — RLS policy kontrol
```sql
-- watchlist tablosunda DELETE policy var mı?
SELECT * FROM pg_policies WHERE tablename = 'watchlist';

-- Yoksa ekle:
CREATE POLICY "users_can_delete_own_watchlist" 
ON watchlist FOR DELETE 
USING (auth.uid() = user_id);
```

### 4.2 — Handler implementation
`app/(tabs)/settings.tsx`:
```ts
const handleClearWatchlist = async () => {
  Alert.alert(
    t('settings.clearWatchlist.title'),
    t('settings.clearWatchlist.confirm'),
    [
      { text: t('common.cancel'), style: 'cancel' },
      {
        text: t('common.delete'),
        style: 'destructive',
        onPress: async () => {
          const { error } = await supabase
            .from('watchlist')
            .delete()
            .eq('user_id', user.id);
          
          if (error) {
            console.error('Clear watchlist failed:', error);
            Alert.alert(t('errors.generic'));
            return;
          }
          
          // CRITICAL: invalidate local cache
          queryClient.invalidateQueries({ queryKey: ['watchlist'] });
          // veya Zustand store kullanılıyorsa: useWatchlistStore.getState().clear();
          
          Alert.alert(t('settings.clearWatchlist.success'));
        },
      },
    ]
  );
};
```

### 4.3 — Cache invalidation
Eğer React Query, SWR, Zustand veya Context API kullanılıyorsa watchlist state'ini explicitly clear et. **DB silme + UI refresh ayrı işlemler.**

**Test:**
- Watchlist'e 3 film ekle → Settings → Clear → onay → watchlist boş ✅
- Cancel basınca silinmemeli ✅
- Network kapalıyken hata mesajı ✅
- RLS test: başka user'ın watchlist'ini silmeye çalışırsa fail ✅
